\section{Limitations}
\label{sec:limitations}

\paragraph{Relation coverage.} Our graph now instantiates four of MAGE-RAG's five relation types (\code{contains}, \code{reading\_order}, \code{layout\_adjacency}, \code{section\_hierarchy}), plus \code{links\_to} for cross-page interconnection, which MAGE-RAG's single-document graph does not need (\S\ref{sec:graph}). The one relation still missing is \emph{semantic-neighbor} edges, which require an embedding model -- naturally, the fine-tuned reader of \S\ref{sec:contrastive} once trained at scale, rather than a separate embedder.

\paragraph{Arbitrary slicing of oversized elements.} The patching rule of \S\ref{sec:tiling} splits an element taller than the maximum tile height into equal-height sub-tiles, with no regard for the element's internal content (e.g.\ a very tall table can still be cut through the middle of a row). This is a narrower, second-order version of PixelRAG's blind-grid failure mode that the rest of the tiling step targets: the cut boundary is only arbitrary \emph{within} a single oversized element, rather than across the whole page, but it is not yet content-aware. Replacing fixed equal-height slicing with a dynamic, resolution-preserving patching scheme (in the spirit of Qwen2-VL's AnyRes-style variable-resolution input) is the natural fix, avoiding both the arbitrary cut and any downscaling/distortion of the sub-tiles.

\paragraph{Lexical relevance scoring in the controller.} The evidence controller (\S\ref{sec:controller}) scores nodes with TF-IDF cosine similarity rather than a learned embedder, so its notion of relevance is purely lexical and will miss paraphrases or cross-modal cues that only the (image-reading) contrastively fine-tuned reader would catch. Wiring the reader's own question--tile similarity into the scoring step is the natural next iteration, and would also let the controller reuse a single learned notion of relevance across mining (\S\ref{sec:contrastive}) and control (\S\ref{sec:controller}) instead of two different mechanisms.

\paragraph{VLM-judge false-negative filter is opt-in, not default.} As described in \S\ref{sec:contrastive}, hard-negative mining's lexical false-negative filter (rejecting a candidate whose text preview contains the answer verbatim) can be supplemented with a VLM-judge filter that inspects each candidate's image directly, catching non-lexical false negatives (a paraphrase, or an answer conveyed visually rather than as text). Because it costs one additional VLM call per surviving candidate, it is not run by default, and the contrastive dataset built so far (\S\ref{sec:experiments}) does not yet use it -- so it remains exposed to exactly the class of false negative it was built to catch until a run is repeated with it enabled.

\paragraph{Single-page scope for mining and (mostly) for control.} Hard-negative mining operates within one page at a time, since tile identifiers are unique only at page scope; mining negatives \emph{across} the pages of a corpus graph (\S\ref{sec:graph}) is a natural extension that would require reusing the same slug-prefixing scheme used to merge per-page graphs. The evidence controller itself already operates over whatever graph it is given, including a multi-page corpus graph, but we have not yet evaluated it at that scale, nor extended its neighbor-propagation step to cross the \code{links\_to} relation into newly-activated pages.

\paragraph{Shallow, non-recursive crawl.} The corpus graph follows hyperlinks one hop deep from a seed page, bounded to a handful of linked pages, to avoid the combinatorial blow-up of a recursive web crawl; this is sufficient to exercise cross-page graph structure but is far short of the scale a genuinely multi-document retrieval setting would require.
