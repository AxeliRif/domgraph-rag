\section{Implementation}
\label{sec:implementation}

The pipeline is implemented in Python and released as an open, modular package, one module per pipeline stage of \S\ref{sec:method}: rendering and geometric extraction via headless Chromium (Playwright, \code{dom\_extraction.py}); tiling, patching, and nested-element pruning over Pillow crops of a full-page screenshot (\code{tiling.py}); graph construction with \code{networkx} (\code{graph\_builder.py}); the reader VLM served either through Ollama (\texttt{qwen3-vl}, the default, requiring no GPU or heavy dependencies) or through Hugging Face \code{transformers} (\code{Qwen2-VL-7B-Instruct}) when LoRA fine-tuning or direct access to hidden states is needed (\code{vlm\_client.py}); synthetic QA generation (\code{qa\_generation.py}); hard-negative mining with \code{scikit-learn}'s TF-IDF and cosine similarity, with a dependency-free token-overlap fallback if \code{scikit-learn} is unavailable (\code{hard\_negative\_mining.py}); and contrastive LoRA fine-tuning with \code{peft} and \code{torch}, LoRA target modules discovered by introspecting the loaded model rather than hard-coded, so the code does not silently no-op if an internal module-naming convention changes across \code{transformers} versions (\code{lora\_finetune.py}).

\paragraph{Oversized-page splitting and graph composition.} \code{sectioning.py} implements the \code{h1}/\code{h2}-boundary split and height-budget fallback of \S\ref{sec:graph} as a pure function over already-extracted DOM elements, independent of the browser and of tiling, so it is unit-testable without Playwright. \code{corpus\_builder.py} separates the network-bound step of a page's pipeline (fetch + extract) from a synchronous core (\code{build\_page\_graph\_from\_elements}) that tiles, decides whether to split, and composes the resulting per-section graphs into one, exposing an \code{entry\_page} attribute on every returned graph; \code{build\_corpus\_graph} (multi-\emph{page} composition, via \code{links\_to}) and the splitting logic (multi-\emph{section} composition of one page, via the new \code{continues} relation) share the same node-namespacing and \code{networkx.compose} machinery, so a linked page that turns out to be oversized is merged into the corpus graph transparently, rewired onto its entry point exactly as an ordinary page would be.

\paragraph{False-negative judging.} The optional VLM-judge filter of \S\ref{sec:contrastive} is a second pass over the candidates that already survived the lexical filter: the candidate tile's image is shown to the reader VLM with the question and the expected answer, and a candidate is discarded if the VLM reports it can recover that answer there. It is opt-in (a \code{vlm\_client} argument to \code{mine\_hard\_negatives}, unset by default) because it costs one VLM call per surviving candidate, on top of the one call per tile already spent on QA generation.

\paragraph{Resolution ablation.} \code{image\_compression.py} exposes \code{compress\_image} (a single Lanczos resize by a linear scale factor) and \code{compress\_images\_dir}, which mirrors an entire flat tile-image directory under a new root with identical filenames; a thin CLI (\code{scripts/compress\_dataset\_images.py}) runs this over the whole dataset built so far. Because it only ever touches image bytes, and \code{ContrastiveTileDataset} already parameterizes its image root, switching a training run between full- and reduced-resolution tiles (\S\ref{sec:contrastive}) is a single \code{-{}-images-root} flag to \code{lora\_finetune.py}, with no other file to regenerate or duplicate.

\paragraph{Batch dataset construction.} A standalone batch script (\code{scripts/build\_dataset.py}) drives the same per-page pipeline -- extraction, tiling, QA generation, and hard-negative mining -- over a list of Wikipedia pages, to grow the single-page dataset used during initial development into a multi-page corpus. Page fetches retry with increasing backoff, so a transient network failure during an unattended, multi-hour run degrades to a delay rather than silently truncating the rest of the page list. The script's unit of work is not the page but a \emph{page unit} -- one page, or one section of a page that had to be split (\S\ref{sec:graph}) -- each with its own slug, generated independently, and checkpointed independently to \code{contrastive\_examples.jsonl} as soon as it finishes; a failure partway through an oversized page therefore costs only the section in flight, not the sections already completed for that page, which matters in practice: an early version of the script lost several hours of work on a single pathologically long page (the one that motivated the splitting design of \S\ref{sec:graph}) because the whole page, not the tile, was the unit of retry.

\paragraph{Demonstration and tests.} An accompanying Jupyter notebook runs every stage end-to-end against live Wikipedia pages, including interactive graph visualizations (state-colored, with tile images embedded in node tooltips) built with \code{pyvis}. Dependency-light unit tests exercise the geometric pipeline (nested-element pruning, adaptive tiling), the graph-construction and oversized-page-splitting logic (section boundaries, the \code{continues} relation, entry-point resolution), hard-negative mining (both the lexical and the VLM-judge filter, the latter with a stub client), and the resolution-compression utilities, all against synthetic fixtures requiring neither network access nor a real VLM or GPU. A separate end-to-end smoke test exercises the full geometric pipeline (DOM extraction through XML export) against a bundled local HTML fixture, requiring Playwright but no external VLM or GPU either, so the core pipeline's correctness can be checked in CI without any paid or rate-limited service.
