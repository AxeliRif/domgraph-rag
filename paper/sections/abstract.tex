Recent visual retrieval-augmented generation (RAG) systems render documents as pixel screenshots and let a vision-language model (VLM) read tiles of the image directly, avoiding the information loss of OCR and text extraction. PixelRAG~\citep{pixelrag2026} popularized this idea but tiles the rendered page on a fixed pixel grid, blind to content boundaries: a table or paragraph can be sliced in half mid-tile. Separately, MAGE-RAG~\citep{magerag2026} organizes long documents into a multigranular page/element evidence graph and reads it with an online controller that activates, opens, and prunes graph nodes under a fixed action budget, but targets already-parsed long PDFs rather than rendered web pages. We present \textbf{DOM-Graph RAG}, a pipeline that replaces PixelRAG's blind grid with tiling guided by the page's own DOM structure: each element's bounding box drives an adaptive tiling and patching procedure that merges undersized elements and splits oversized ones, so tile boundaries follow content boundaries by construction. The resulting tiles are organized into a MAGE-RAG-style two-level graph (page and element nodes, connected by containment and spatial reading-order edges) that we further extend across pages via hyperlink edges into a small multi-page corpus graph. We fine-tune a VLM reader contrastively on synthetically generated (tile, question) pairs with lexically-mined hard negatives, using LoRA adapters on both the vision tower and the language decoder and an InfoNCE objective. Finally, we implement an online evidence controller that evolves every node's state through a four-state machine (\state{inactive} $\to$ \state{active} $\to$ \state{opened}/\state{pruned}) via a best-first search under a node-opening budget, so the reader receives a small, prioritized evidence subgraph instead of the whole page. We describe the full, open-sourced pipeline and its implementation choices in detail, and lay out the evaluation protocol against MAGE-RAG's published LongDocURL and MMLongBench-Doc numbers; end-to-end benchmark results are ongoing work, reported as a work-in-progress in Section~\ref{sec:experiments}.
